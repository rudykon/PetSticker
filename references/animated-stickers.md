# 动态表情包：生成、检查与优化

本参考用于 GIF 动态宠物表情。先遵守主 Skill 的角色锁定、微信素材规格和人工验收要求；这里仅补充逐帧动画特有的方法。

## 1. 先把动画规格写进清单

在生成前确定并记录：画布、帧数、完整循环时长、循环方式、透明背景、单文件上限、文字是否静止，以及用户是否允许插值。不要把“帧数”“每帧延时”和“完整循环时长”混为一谈。

例如用户要求 12 帧、2.00 秒，而 GIF 延时以 10 ms 为常见最小单位时，可使用：

```text
170, 170, 160, 170, 170, 160, 170, 170, 160, 170, 170, 160 ms
```

总和正好 2000 ms，误差均匀分布。该数值只是满足这一特定要求的方案，不是所有专辑的固定默认值。

动态 manifest 至少记录：

```json
{
  "frame_count": 12,
  "frame_delays_ms": [170, 170, 160, 170, 170, 160, 170, 170, 160, 170, 170, 160],
  "loop_duration_ms": 2000,
  "animation": {
    "format": "GIF",
    "loop": "infinite",
    "static_text": true,
    "frame_method": "directly generated action drawings; no interpolation"
  }
}
```

## 2. 用语义动作拆帧，不让整张贴纸摇晃

动画主体应是宠物和主题所需道具。禁止用整张图的平移、旋转、缩放、抖动或裁切缩放冒充角色动作。

先把一句主题拆成有意义的动作阶段：

1. 起始姿势；
2. 预备动作；
3. 动作展开；
4. 主要接触或发力；
5. 动作峰值；
6. 峰值保持或次级动作；
7. 回收动作；
8. 恢复姿势；
9. 连接回首帧的过渡。

帧数多于阶段数时，增加真实的中间姿势，而不是复制帧或对像素做变形。例如“吃瓜”必须表现抱住西瓜、靠近嘴边、张嘴、咬下、拉开、鼓腮咀嚼、吞咽和再次举起；仅让猫上下晃动不算完成主题。

循环动画的末帧应在姿势、重心和视线方向上接近首帧，但不要机械复制首帧造成停顿。

## 3. 直接生成连续动作图

质量优先或用户禁止插值时，每一帧都应是完整生成/绘制的动作图。不要使用 RIFE、光流、形变补帧，也不要从一张原图裁出不同区域拼成伪动作。

可先生成一张带安全间隔的 4×3 十二格动作故事板，再逐格提取；“逐格提取”只是把已经独立生成的动作格导出，不是裁切一张静态猫图来制造动作。故事板应满足：

- 每格都是同一宠物、同一画风、同一项圈和毛色；
- 每格有完整动作姿势与安全边距，耳尖、尾巴和伸展肢体不跨到相邻格；
- 不在故事板里生成最终文字；文字后期单独合成；
- 不添加用户未要求的星星、感叹号、彩带、爱心、亮片或运动线；
- 道具只在主题需要时出现，并在相邻帧保持形状、大小和接触关系。

若某一帧身份、解剖或道具失真，只重新生成失败帧。把前后相邻的合格帧作为姿势和身份参考，明确要求“位于两帧之间的真实中间动作”，不要对失败帧继续插值或修补变形。

## 4. 透明背景与逐帧抠图

优先直接生成透明背景。必须使用绿幕时，先分离主体和白色贴纸描边，再清理绿幕；不要只做全图颜色阈值删除。

常见残绿有两类：

- 与透明背景相连的绿边：用邻近透明像素和连通域清理；
- 被身体、尾巴或四肢包围的封闭绿色块：以高饱和绿为种子，向相连的柔和绿边扩张后整体清除。

强清理规则只能用于确认使用绿幕且没有合法绿色道具的角色区域。西瓜、绿色项圈珠、衣服等合法内容必须保护；不要把“绿色像素为零”设成所有表情的通用要求。

逐帧检查透明边缘、封闭孔洞、毛发缺口、隐藏 RGB、棋盘格和方形底板。绿幕自动阈值只能发现候选问题，最终仍需在深色、浅色和高饱和彩底上目视确认。

## 5. 文字必须是唯一静态图层

模型生成的逐帧文字容易错字、变形和晃动。可靠流程是：

1. 所有动作帧只生成猫和道具，预留固定文字区；
2. 在最终画布尺寸创建一张文字 RGBA 图层；
3. 对中文逐字核对；需要手写感时使用授权明确的手写字形，并可给每个字设置固定的轻微倾斜、大小和基线差异；
4. 把同一份文字图层以同一坐标合成到全部帧；
5. 用像素锁定检查确认 12 帧文字区完全一致。

“手写的不规则”必须在生成文字图层时固定，不能让角度、大小、位置或笔画随帧变化。

## 6. GIF 编码与体积优化

编码顺序建议：

1. 保留无损 RGBA 帧作为工作源；
2. 统一画布和固定文字图层；
3. 为整张 GIF 建立共享调色板，避免每帧颜色漂移；
4. 使用真实透明索引和明确的 disposal；
5. 写入逐帧延时与无限循环；
6. 最后再做体积优化。

体积超过用户上限时，按以下优先级处理：

1. 删除元数据和无效隐藏颜色；
2. 使用全局调色板并减少相近颜色；
3. 在不破坏毛发和描边的前提下降低调色板颜色数；
4. 优化透明阈值和重复区域；
5. 最后才考虑减少帧数或缩短画面内容，并先取得用户同意。

不要为了压缩而优先删除关键动作帧、放大透明阈值或破坏猫毛边缘。对于 240×240、12 帧的贴纸，128–192 色通常是可测试的起点，不是强制值。

## 7. 四层动态验收

### A. 文件与时间轴

- 文件数量、编号、格式和 manifest 一致；
- 每帧画布尺寸相同；
- 帧数、逐帧延时、总循环时长和无限循环符合要求；
- 每张低于用户体积上限；
- 每帧含真实透明区域，画布边缘没有非透明裁切。

### B. 身份、解剖和道具

- 每帧都是同一宠物与体型；
- 四肢、爪、尾巴数量与连接正确；
- 相邻帧没有脸型突变、毛色漂移、项圈跳变或道具穿模；
- 道具动作确实对应主题。

### C. 运动与过渡

- 只让猫和必要道具运动；文字与画布不动；
- 逐帧变化方向连贯，没有突然反向、瞬移或复制停顿；
- 峰值动作可读，首尾衔接自然；
- 在实际播放速度下检查是否过快、过慢或节奏不均；
- 逐帧总览中检查模型失真，实际播放中检查时间感。

### D. 透明、文字和小尺寸

- 每帧在多种彩底上无绿边、白边、孔洞或误删毛发；
- 文字逐字准确，固定像素不一致数为零；
- 在 240×240 下动作和文案仍清楚；
- GIF 调色板没有导致脸、眼睛或文字明显色带。

运行自动检查：

```bash
python3 scripts/validate_album.py /absolute/path/to/release \
  --expected-stickers 24 --allow-gif-stickers \
  --gif-frames 12 --gif-loop-ms 2000 \
  --require-infinite-loop --require-transparent-gif \
  --with-tipping --require-qa-docs

python3 scripts/make_contact_sheet.py \
  /absolute/path/to/release/stickers /absolute/path/to/first_frames.png

python3 scripts/make_animation_sheet.py \
  /absolute/path/to/release/stickers /absolute/path/to/all_frames.png
```

若每帧延时也必须精确一致，再向验证命令加入：

```bash
--gif-frame-delays "170,170,160,170,170,160,170,170,160,170,170,160"
```

把数值替换为 manifest 中的实际列表。

自动检查不能证明身份、解剖、动作语义或过渡自然，仍必须查看逐帧总览和实际播放。

## 8. 按问题类型优化

| 问题 | 优先修复方法 | 不要做 |
|---|---|---|
| 整张贴纸摇晃 | 固定画布与文字，只重新设计猫的局部/全身动作 | 用全图平移旋转冒充动作 |
| 主题不对应 | 重新拆分主题的接触、发力、峰值和恢复动作 | 只改变表情或上下浮动 |
| 动作太快 | 增加完整循环时长并重新核对实际播放 | 盲目复制相同帧 |
| 过渡粗糙 | 直接生成更多真实中间姿势 | 使用 RIFE/光流插值掩盖缺帧 |
| 个别帧失真 | 仅重生成失败帧，并引用前后合格帧 | 将失败帧加入后续参考链 |
| 文字晃动 | 单独生成一次文字图层并像素锁定 | 每帧重新生成或排版文字 |
| 透明背景破损 | 返修蒙版、连通域和封闭绿块 | 用全图粗阈值误删浅色毛发/绿色道具 |
| 首尾跳变 | 让末帧姿势和动势回到首帧附近 | 直接复制首帧造成停顿 |
| 超过体积上限 | 先优化调色板、隐藏颜色和元数据 | 首先删关键帧或破坏边缘 |

每次只修复一种明确缺陷并重新检查全部门禁。局部返修后也要重新编码和验证整张 GIF，因为调色板、透明索引和总时长可能随之变化。
